# Beacon 与 GameHub 功能对比

分析日期：2026-10-16。目标为用户设备已安装的 Beacon 1.9.0.2（versionCode 69），包名 `com.radikal.gamelauncher`；主 APK SHA-256 为 `fcd80ad2225375e02a91e4193c7835c9c997ebc197953ba3b026a86bf1259851`。

分析使用 REA 6.5.0、JADX headless 0.7.1，以及 ADB 界面观察。只记录行为与数据契约，GameHub 独立实现；仓库不包含 Beacon APK、反编译源码、第三方凭据或素材。静态调用关系不能证明运行时行为。设备上的 Beacon 尚无已配置平台，所以未实测游戏运行、平台切换和在线刮削成功率。

## 功能差异与本次范围

| 方面 | Beacon 证据 | GameHub v1.1.1 | v1.2.0 与后续工作 |
|---|---|---|---|
| 平台切换 | 平台有顺序、名称和短名；添加界面支持平台类型、播放器 App、ROM 目录和图片比例 | 已有标签切换、L1/R1、平台排序和空平台隐藏 | 保留现有操作；增加六种外部平台。每平台选中项目记忆是后续体验建议，未确认为 Beacon 行为 |
| 平台范围 | 平台类型含 Custom，配置与平台实例分开 | 固定十种平台 | 新增 PS2、DS、3DS、GameCube、Wii、Dreamcast；任意自定义平台、多实例仍未实现 |
| ROM 目录 | `GamePlatformPath` 独立表，平台保存接口接收目录列表 | 每平台一个目录 | 多目录仍待实现，需定义重复文件识别、扫描失败保护与目录撤销行为 |
| 游戏资料 | 发行日期、类型、开发商、发行商；UI 调用这些字段展示 | 主要是名称、文件信息、封面和右侧图片；已有最近游玩 | 完整元数据仍待实现：持久化、刮削填充、手动编辑、备份、重扫保留，再加入右侧预览。此版本 Game 模型未见简介字段 |
| 图片 | 封面与截图独立保存，Libretro 有各自的下载路径 | 预览图与宫格图独立，但两种搜索均偏向封面 | 预览搜索 Libretro `Named_Snaps`，宫格搜索 `Named_Boxarts`；其他来源仍可能返回封面 |
| 批量刮削 | 按平台找缺失资料，逐游戏处理，报告进度、间隔请求 | 编辑页单游戏候选搜索 | 待实现可取消的“仅补缺失”队列、进度、失败重试和断点恢复；不应覆盖用户手工图片 |
| 来源调度 | 来源启用、排序、限流状态；逐源补全至资料齐全 | 四种来源，固定顺序、候选截断 | 待实现优先级、限流冷却和统一错误提示；继续使用用户自己的服务凭据 |
| 匹配 | Libretro 索引、相似度与地区偏好 | 标题变体构造并逐 URL 检查 | 可使用公开索引缓存、序列号及相似度候选；不复制 Beacon 内置索引或服务密钥 |
| 模拟器启动 | 平台保存播放器包、核心、文件处理类型、启动命令；解析成 Android Intent | 包选择与预置适配主要写在代码中 | 新增结构化平台级配置：Activity、Action、MIME、Data URI、基础类型 extras；不执行 shell 命令 |
| 单游戏覆盖 | Game 模型有播放器包和核心字段 | 平台级选择 | 单游戏播放器/核心覆盖、专门的 RetroArch 核心选择器仍待实现 |

## 使用新增平台与启动配置

1. 在 Android 上先安装所需模拟器。
2. GameHub **设置 → 平台管理 → 模拟器 → 添加其他**，选择平台，授权 ROM 目录。
3. 选择已安装模拟器。未在推荐列表中出现时使用“全部”或搜索；刚安装的应用可点“刷新应用”。
4. 通常保持自动适配；需要明确参数时进入平台的“启动配置”。Activity 可从该 App 导出的 Activity 中选择；具体可接受参数以模拟器文档为准。
5. `{romUri}` 替换为已授权的 ROM content URI，`{gameTitle}` 替换为游戏原始名称。例如 extras `{"ROM":"{romUri}"}` 仅说明语法，不是所有模拟器的通用参数。支持字符串、布尔值和数字，拒绝嵌套/重复键/非法 JSON。
6. 扫描后回到平台列表启动。新增平台没有内置核心。依赖真实文件路径、目录中其他轨道文件或专用核心参数的模拟器可能需要进一步适配；自定义配置不会自动把 URI 变为真实路径。

自定义配置默认关闭，旧版平台配置继续有效；旧平台标识、收藏、排序、图片迁移和存档布局不变。更换模拟器 App 时清除旧 App 的自定义参数，同一 App 重选时保留。配置随现有设置备份保存；它不用于保存账号口令。自定义启动失败会报错，不会悄悄改走其他启动方式。

## 实现顺序建议

1. 本次已补平台入口、可编辑启动配置及截图/封面搜索分工，先收集不同模拟器的实测结果。
2. 建立可选游戏元数据结构及重扫合并策略，再连通刮削与右侧资料显示。
3. 在相同数据模型上实现按平台批量补缺、取消/重试、来源优先级和限流提示。
4. 增加多目录和单游戏启动覆盖；为经过实测的模拟器提供默认配置模板。

## v1.2.0 验证范围

- Debug/Release 构建、Release lint 和 45 项 JVM 单元测试通过；三语 594 个键同步。
- 已在 vivo V2310 / Android 15 上覆盖升级，确认发布签名与旧版本一致。手机横屏及临时 160 dpi 平板逻辑宽度下检查配置弹窗、滚动和操作按钮，随后恢复设备原密度。
- 真机验证应用选择、配置启用与保存后重开、恢复自动适配、非法 JSON 禁止保存及清除绑定。测试临时绑定已撤销。测试期间发现并修复了 JVM 与 Android ICU 对未转义右花括号的正则兼容差异。
- A/B、L1/R1、L3/R3 复用原有共享页面与回调，未删除现有操作；实体手柄、新平台实际 ROM 启动及所有在线图片来源成功率尚未实测。模拟器启动 Intent 被系统接受不代表游戏已经运行成功。
